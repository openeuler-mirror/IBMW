# 自研零拷贝共享内存传输（shm_ext）— 使用与迁移说明

本文说明自研共享内存传输与 iceoryx 的关系、构建开关、运行时如何选择、与 iceoryx 驱动的行为差异，以及目前**没有**替代的部分。测试与验证记录见 [测试文档.md](测试文档.md)，性能对标见 [对标基准.md](对标基准.md)。

## 1. 结论

- **可选**：shm 由构建开关 `IBMW_BUILD_SHM_EXTENSION` 控制，默认 OFF。关闭时不构建 shm 库与扩展，已有构建（含 iceoryx）不受影响。
- **与 iceoryx 独立**：shm 是一个**新的传输扩展**（`src/extensions/transport/shm_ext`），不是 iceoryx_ext 的后端，也不链接 iceoryx。两个扩展可以只开一个，也可以同时编进一个构建、同时加载到一个进程。
- **没有完全替代 iceoryx**：数据面（发布/订阅、loan、POD/ctx-meta 帧、兼容 API、CLI、ibmw_gen）已经可以替代。iceoryx 专属的验证器（`retained_loan_e2e`）、Reporter V1 桥接等仍然只有 iceoryx 版本；原 iceoryx 示例已有 shm 对应版本（见 §6）。iceoryx_ext 与核心代码均未改动。

## 2. 组成

| 部分 | 位置 | 说明 |
|---|---|---|
| 共享内存库 `ibmw_shm` | `selfdev/shm/` | 段（memfd，可封只读）、发布/订阅环、Listener、服务目录（unix socket）。只依赖 Linux 内核接口（memfd/futex/epoll），无第三方库、无守护进程 |
| 传输扩展 `shm_ext` | `src/extensions/transport/shm_ext/` | IBMW 传输驱动 `ShmTransportDriver`，插件库 `libibmw_shm_transport.so`，扩展名 `shm_extension` |
| 兼容 API | `shm_ext/iox_style_publisher.h` | 与 `iceoryx_ext/iox_style_publisher.h` 同名同签名（`IoxStylePublisher<T>`、`CreatePodPublisher<T>`、`CreateCtxMetaPublisher` 等），命名空间 `ibmw::extensions::shm_extension`。签名中的驱动类型 `IceoryxTransportDriver` 是 `ShmTransportDriver` 的别名 |
| 基准通道 | `src/samples/cpp/transport_benchmark/shm_*` | `shm_send`、`shm_loan_v2`、`shm_loaned_pod`、`shm_loaned_ctx`，复用对应 `iox_*` 通道的源码，只换配置 |
| CLI | `ibmw topic pub ... --shm` | 选项 `--shm-*`，见测试文档 §6.4 |
| ibmw_gen | `transports/shm.py` | `transport: shm`、`direct_shm_*`、`wire.shm` |

## 3. 构建开关

| 选项 / 预设 | 作用 |
|---|---|
| `IBMW_BUILD_SHM_EXTENSION` | 构建 `ibmw_shm` 与 `shm_ext`（依赖 `IBMW_BUILD_RUNTIME=ON`；仅 Linux 内核，含 OHOS，其他系统配置时报错） |
| `IBMW_BUILD_ICEORYX_EXTENSION` | 构建 iceoryx_ext 与 iceoryx（不变） |
| `IBMW_BUILD_BENCHMARKS` | 需要 `IBMW_BUILD_EXAMPLES=ON`，且 iceoryx 与 shm 至少开一个（原来强制 iceoryx）。各通道按自己的传输是否开启自行跳过，所以在 Linux 主机上只开 shm 时得到 4 条 shm 通道、没有 iceoryx 目标（OHOS 交叉构建的基准树只有 `iox_loaned_ctx`，没有 shm 通道）。基准负载使用 CDR 序列化，仍需 Fast CDR/Fast DDS（`dds_types`） |
| 预设 `shm` | 继承 `dev`，开 shm、关 iceoryx，构建目录 `build-shm`：`cmake --preset shm && cmake --build --preset shm` |
| 预设 `iceoryx` | 不变 |
| 预设 `full` | 在 iceoryx 之外同时开 shm（驱动名 `shm`，两者不冲突）；因此 `full` 只能在 Linux 内核上配置 |

开启 shm 时生成的编译期宏：`IBMW_HAS_SELFDEV_SHM=1`；`IBMW_HAS_SHM`（= iceoryx 或自研 shm）在只开 shm 时也为 1，`LoanedSample` 等按它启用共享内存相关断言（`cmake/IbmwTransportFlags.cmake`、`cmake/transport_features.h.in`）。

常用组合：

```bash
# 只用 shm（不拉取 iceoryx，不需要 RouDi）
cmake -S . -B build -DIBMW_BUILD_SHM_EXTENSION=ON
# shm 基准（不含 iceoryx）
cmake -S . -B build -DIBMW_BUILD_SHM_EXTENSION=ON -DIBMW_BUILD_EXAMPLES=ON -DIBMW_BUILD_BENCHMARKS=ON
# 两者共存（对比或分批迁移）
cmake -S . -B build -DIBMW_BUILD_SHM_EXTENSION=ON -DIBMW_BUILD_ICEORYX_EXTENSION=ON
```

两者同时开启时，目标、命名空间、驱动槽位（`shm` 与 `iceoryx`）都不冲突。两个插件库都导出的强符号只有插件入口 `IbmwExtEntryV2`，它按库句柄 `dlsym` 查找，不会混用。开关组合由 `selfdev/shm/scripts/run_shm_switch_check.sh` 检查（测试文档 §6.10）。

## 4. 运行时选择

进程用哪个传输由配置决定，与构建了哪些扩展无关。

### 4.1 YAML

```yaml
ibmw:
  extensions:
    items:
      - name: shm_extension
        path: ./libibmw_shm_transport.so
        options:
          driver_name: shm          # 缺省 shm；写 iceoryx 即原位替换
          runtime_id: my_app
          # domain / root_dir / group / shm_init_size / ... 见测试文档 §6.2
  messaging:
    drivers:
      - type: shm
    publishers:
      - topic: "(.*)"
        enable_drivers: [shm]
    subscribers:
      - topic: "(.*)"
        enable_drivers: [shm]
```

**原位替换**（不改 messaging 段与按名查找的代码）：把扩展项从 `iceoryx_extension` / `libibmw_iceoryx_transport.so` 换成 `shm_extension` / `libibmw_shm_transport.so`，并设 `driver_name: iceoryx`。`messaging` 段中的 `type: iceoryx`、`enable_drivers: [iceoryx]` 与按名查找 `"iceoryx"` 的代码都不用改。`shm_send` 等基准通道的配置就是这种写法。

按**槽位**绑定驱动的模块不在此列：槽位是驱动的 C++ 类型，shm 恒为 `shm`（§5）。用 `IBMW_USE_DRIVER(iceoryx_extension::IceoryxTransportDriver, ...)` 的模块、ibmw_gen 生成的 `direct_iceoryx_*` 模块拿不到 shm 驱动，要改为 shm 版本（包含 `shm_ext` 头文件、换命名空间，或重新生成为 `direct_shm_*`），见 §7 第 2 步。

### 4.2 驱动名不能重复

核心按名字选驱动，取**第一个**注册的同名驱动，后来的同名驱动不会被使用，核心也不报错（已转交核心维护方，问题清单 C9）。所以：

- 同一进程同时加载 `iceoryx_extension` 与 `shm_extension` 时，shm 的 `driver_name` 不能是 `iceoryx`。shm_extension 在初始化时检查这一点，发现冲突即启动失败，报错 `driver_name 'iceoryx' is also registered by extension 'iceoryx_extension'`（EXT-61）。共存时用缺省 `driver_name: shm`。
- 共存时 `messaging.drivers` 中两个驱动都要列出（`type: iceoryx` 与 `type: shm`），主题用 `enable_drivers` 选择。只加载 `iceoryx_extension` 而不启用它的驱动，进程退出时 iceoryx_ext 报 `Fatal ... IceoryxBus::Shutdown requires successful shutdown preparation` 且不释放资源（退出码仍为 0；与 shm 无关，问题清单 C10）。
- `driver_name: local` 与内置的 local 传输重名，同样被拒绝。
- 检查依据扩展名约定：驱动 `<x>` 由扩展 `<x>_extension` 注册；例外是 `net_extension`，它注册 `tcp`、`udp`、`http`，也已列入检查。不遵循该约定的第三方扩展若注册同名驱动，检查不到，需部署方避免。

### 4.3 CLI 与代码生成

- `ibmw topic pub <topic> <type> <json> --shm [--shm-domain ...]`。`--shm` 与 `--iceoryx` 二选一，选项对照见测试文档 §6.4。
- ibmw_gen：`transport: shm` 或 `direct_shm_publisher`/`direct_shm_subscriber`。同一应用混用 iceoryx 与 shm 模块时生成报错。

## 5. 与 iceoryx 驱动的行为差异

| 项目 | iceoryx_ext | shm_ext |
|---|---|---|
| 守护进程 | 先启动 RouDi | 无。发现靠服务目录 `<root_dir>/ibmw_shm.<euid 或 g<gid>>.<domain>` 下的 unix socket。domain 最长 32 个字符，服务目录最长 63 字节（socket 路径要放进 `sun_path`），超长时 Initialize 报错 |
| 互通 | — | **不与 iceoryx 互通**：shm 发布者到不了 iceoryx 订阅者。同一主题的所有进程要一起切换 |
| 驱动槽位 | `iceoryx` | 恒为 `shm`（与 `driver_name` 无关） |
| `publish()` 返回值 | 有效样本恒为 true | 如实返回（无效样本、重复/过期 loan、外来句柄为 false） |
| Reporter V1 core metrics 桥接 | 有 | **不提供**；统计只在初始化报告与 `ShmBus::Stats()` |
| URL / loan 限制 | 超长名居中截断 | URL 编码后超过 1024 字节拒绝注册；loan 对齐上限 4096；单次 loan 上限 256 MiB；每个发布者的共享内存缺省上限 512 MiB（`max_bytes_per_publisher`） |
| domain | — | 一个进程只运行一个 shm domain，冲突时 Initialize 抛错 |
| 存储位置 | iceoryx 管理 `/dev/shm/iceoryx_*` | memfd 段；服务目录缺省 `/dev/shm` 或 `/tmp`。**OHOS 无缺省**，须设 `root_dir` 或 `IBMW_SHM_ROOT`。`domain`、`group` 未配置时分别取 `IBMW_SHM_DOMAIN`、`IBMW_SHM_GROUP` |
| 多用户 | RouDi 配置 | `group`（数字 gid）：目录 0770、socket 0660，同组用户可通信 |
| 只读保护 | — | 内核支持时把发布段封为只读；`require_read_only: true` 时不支持就拒绝发布 |
| 关闭失败 | — | 仍有未归还 loan 或回调停滞时记录 MW_ERROR 并有意泄漏共享内存对象，不在被引用时释放 |
| `benchmark_profile` | 支持 `core_metrics_e2e_lossless_v1` | 规则相同：全部省略（旧缺省）或恰好该 profile |

更多细节（Start 前样本、监听线程选项、初始化报告字段）见测试文档 §6.2。

## 6. 未替代（仍只有 iceoryx 版本）

下列内容没有 shm 版本，需要它们时仍要构建 iceoryx：

| 项目 | 说明 |
|---|---|
| Reporter V1 / core metrics 桥接 | iceoryx_ext 的 `reporter_bridge`、`core_metrics_perf.py`。依赖这些指标的部署迁移后不再有 |
| 示例源码 | `shm_inproc_demo`、`shm_interproc_demo` 编译 `iceoryx_inproc_demo`、`iceoryx_interproc_demo` 的源码（只覆盖标题与提示字符串），删除 iceoryx 示例前需先拆分 |
| 验证器与门禁 | `retained_loan_e2e`（`IBMW_BUILD_RETAINED_LOAN_E2E`） |
| ROS 2 导入 | `ibmw-gen import --target shm` 只输出元数据与 lowering 计划（与 iceoryx 相同），不做更多 lowering |
| 基准源码 | shm 通道复用 `iox_*` 源码，iceoryx 通道源码删除前需先拆分 |
| 非 Linux | shm 只支持 Linux 内核（含 OHOS） |

下列示例与门禁已经支持 shm，只开 shm 时可直接使用：

| 项目 | 现状 |

## 7. 迁移步骤

1. 构建：打开 `IBMW_BUILD_SHM_EXTENSION`；验证完成前可与 iceoryx 共存。
2. 代码：`#include "shm_ext/iox_style_publisher.h"`，命名空间换成 `ibmw::extensions::shm_extension`（其中 `IceoryxTransportDriver` 是 `ShmTransportDriver` 的别名，`IBMW_USE_DRIVER` 因此绑定 shm 槽位），CMake 链接 `ibmw::extensions::shm_ext`（不再需要 `iceoryx_posh`）。ibmw_gen 生成的模块改为 `transport: shm` 后重新生成。只有按名查找驱动的代码在原位替换时不用改。检查依赖 `publish()` 恒为 true 的调用方。
3. 配置：按 §4.1 改扩展项。原位替换时设 `driver_name: iceoryx`，并去掉同一进程中的 `iceoryx_extension`（否则启动失败，见 §4.2）。OHOS 上设置 `root_dir`。
4. 部署：同一主题的所有进程一起切换；不再启动 RouDi（其他仍用 iceoryx 的进程除外）。
5. 观测：Reporter V1 指标不再有，改看初始化报告与 `Stats()`。
