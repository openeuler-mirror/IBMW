# iceoryx_inproc_demo

Single-process pub/sub demo built on top of the Iceoryx shared-memory
transport extension (`libibmw_iceoryx_transport.so`). Publisher and
subscriber modules live in **the same OS process**; the transport still
goes through the Iceoryx RouDi daemon and shared-memory chunks, so the
zero-copy code path is exercised end-to-end.

## What this demo proves

- The Iceoryx transport extension can be loaded as a regular IBMW transport
  and used by **two managed modules in the same process** without any
  per-process registration tax.
- The `sensor::CompressedImage` IDL type (provided by
  `ibmw::schema::sensor_idl_gencode` via `WRAP_IDLS CompressedImage`) is
  re-used unchanged — no hand-written `cdr_impl.cc` shim. CDR
  (de)serialization is fully generated by the schema target.
- Crafted "large payload" frames exercise the iox SHM auto-grow path inside
  a single process before the same code is reused by `iceoryx_interproc_demo`
  for the cross-process variant.

## Layout

| Path | Role |
|------|------|
| `managed/publisher_module/` | `publisher_module.{h,cc}` — periodic publisher of `sensor::CompressedImage` |
| `managed/subscriber_module/` | `subscriber_module.{h,cc}` — receives + logs frame metadata |
| `managed/compressed_image_dds_types.h` | Public type alias header (IDL types come from `ibmw::schema::sensor_idl_gencode`) |
| `standalone/pubsub_app/main.cc` | App-mode entry — registers both modules, drives one `Engine` instance |
| `config/linux/bin/cfg/iceoryx_inproc_cfg.yaml` | Loads `iceoryx_extension`, wires both modules to the same topic |
| `config/linux/bin/start_iceoryx_inproc.sh` | Convenience launcher that starts `iox-roudi`, runs the app, then tears RouDi down |
| `CMakeLists.txt` | Two `STATIC` module libs + one `iceoryx_inproc_app` executable; `DEPENDS ibmw_extensions_iceoryx_ext` |

## Build

Gated by `IBMW_BUILD_ICEORYX_EXTENSION`:

```bash
cmake --preset full -DIBMW_BUILD_ICEORYX_EXTENSION=ON
cmake --build build -j$(nproc)
```

Skipped automatically (with a `Skip iceoryx_inproc_demo because
IBMW_BUILD_ICEORYX_EXTENSION is OFF` status) on minimal preset runs.

## Run

```bash
cd build
bash start_iceoryx_inproc.sh
```

The helper script:

1. Starts `iox-roudi` in the background.
2. Runs `./iceoryx_inproc_app cfg/iceoryx_inproc_cfg.yaml` for ~5s.
3. Tears RouDi down using the sample's explicit process cleanup sequence
   (`ps -ef | grep iox-roudi | grep -v grep | awk '{print $2}' | xargs kill -9`),
   never `pkill`.

Manual run (RouDi already running):

```bash
cd build
./iceoryx_inproc_app cfg/iceoryx_inproc_cfg.yaml
```

## Expected behavior

The subscriber logs one `[CompressedImage] received format=... data_size=...`
line per published frame. There are no allocations on the hot path — the
publisher loans an SHM chunk, copies the payload into the chunk, and
publishes; the subscriber reads from the loaned chunk in place.
