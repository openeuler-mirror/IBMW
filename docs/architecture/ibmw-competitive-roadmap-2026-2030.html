02 / PHASE 0→1

2026 · 可信替代

兼容不交性能税；
先把基座做成证据

以 ROS 2 生态为入口，同时完成数据连接基础框架、轻量运行时和可复现对标。竞争优势是迁移成本低、资源开销低、性能路径可解释。

2026 的核心不是堆功能，而是让同一份应用资产在 IBMW 上进得来、跑得轻、比得公平。

04 / PHASE 10→100

2028—2030 · 规模化复制

跨域确定性，
规模化协同

该阶段不再规划首次建设 MQTT、Zenoh 或云边 / 边端连接，而是深化 2026 基础框架与 2027 协同策略，复制到更多平台、业务与生态，并由契约和认证治理边界。

规模化的竞争力：同一套确定性承诺跨平台复验，软件包原生消费 IBMW 优势。

PLATFORM

适配方法复制

从 310P RC 计划验证路径扩展至多 SoC、加速器与 RTOS / MCU，减少重复移植。

BUSINESS

业务域原生使用

覆盖 SLAM、VLA、WBC、感知、规划控制与大小模型，让通信、调度、预算成为业务优势。

端侧闭环云边协同边端协同
ECOSYSTEM

连接与能力治理

以 MQTT / Zenoh 和云边 / 边端拓扑承载跨域协同；以 API / ABI、Schema、Profile、fallback 契约化演进。

跨域确定性能力协商可审计
EVIDENCE

认证与真实数据复利

真实负载、故障注入、长稳与回归证据进入持续交付，新平台继承方法而非重建可信度。

统一口径版本回归支持等级
2028 / REPRODUCE完成首次复制

建议：除 310P RC 外 ≥2 个认证 Profile、≥2 类重点负载；适配周期 P50 ≤12 周；核心软件包原生能力使用率 20%。

2029 / PRODUCTIZE形成规模交付

建议：累计 ≥4 个受控 Profile、≥3 类重点负载；适配周期较 2028 缩短 40%；原生能力使用率 50%。

2030 / ECOSYSTEM建立生态门槛

建议：累计 ≥6 个认证 Profile、≥5 类具身业务域；适配周期较 2028 缩短 60%；原生能力使用率 80%，认证矩阵回归 100%。

受控边界：每年冻结首批 Platform Profile、重点业务、支持等级和排除项；新增平台须通过资源发现、调度映射、传输、RTOS 对接及统一验收门禁。未进入 Profile 的平台不构成支持承诺。以上为规划目标。

05 / COMPOUNDING MOAT

为什么会赢

边界清晰，
证据复利

ROS 2 提供接口资产与生态惯性；IBMW 在具身关键约束上给出更强答案，并把每次验证沉淀为下一次交付的确定性资产。

01 / ENTER

兼容降低采用门槛

复用 ROS 2 接口类型与 Fast DDS 互通，运行时保持独立。

02 / PROVE

公平证据赢得信任

同硬件、负载、QoS、优化条件；A / B / C 证明迁移与快路径价值。

03 / DEEPEN

具身闭环形成差异

通信、计算、异构资源与 RTOS 控制预算贯通。

04 / REPEAT

契约和方法复制确定性

从 310P RC 的计划验证路径抽象 Profile、适配与认证规则。

05 / COMPOUND

真实失效数据增厚壁垒

版本、工况、故障与恢复数据回流，提升策略、诊断与认证可信度。

最终要证明的不是功能删减，而是：兼容得更低成本；在具身关键链路上，运行得更快、更稳、更可证明。
